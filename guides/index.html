Why guides

A general-purpose agent is a generalist. Your trail isn't.

The same agent that writes the code shouldn't be the one that signs it off, and a security pass needs a different eye than a docs pass. Guides give each kind of work its own instructions and its own bar.

How it works

Pick a guide, give it a ticket, and the work meets its checklist.

  • 01

    Pick a guide

    Five come built in. Add more from a reviewed catalog, or write your own: a short file with instructions, a checklist and the checks it needs.

  • 02

    Give it a ticket

    Each ticket can ask for a guide, and each trail lists its team. Pick them in the Lookout, or let your agents suggest them when they plan the trail.

  • 03

    The work meets the checklist

    The agent that takes the ticket gets the guide's instructions and checklist, and can't finish until it has answered every item.

Every answer, on the ticket

The checklist answers stay with the ticket: who answered, when, and a note on anything not done. You see them in the Lookout next to the work.

Safe by design

A guide can raise the bar. Never lower it.

Bringing someone in from a catalog has to be safe by default. These rules are enforced by Teamtrail, not by the guide.

  • No code in a guide

    Guides are instructions and checklists. No scripts, no hooks, nothing that runs when you add one.

  • You approve every check

    A command a guide proposes runs only after you approve it, and it goes into your repo's config.

  • Pinned and verified

    Each guide you add is pinned to a version and fingerprint. A file that changes is switched off until you look.

  • Guides only add rules

    A guide can add checks and checklist items. It can't skip review, lower verification or decide for you.

Any agent, any model

Guides aren't tied to a model.

A guide is plain text that travels with the ticket. Claude Code, Codex or any agent you connect picks it up when it takes the work. No vendor lock-in, no hosted agents, and still all on your machine.

Write your own

Your team's know-how, in one short file.

A guide is a markdown file: a few lines about it, a checklist, and plain steps for the agent. One command starts it from a template, and you make it yours.

  • 01

    Write it

    teamtrail guides new <id> writes a template that already passes the lint. Change the name, the checklist and the steps. The docs list every field.

  • 02

    Check it

    teamtrail guides lint checks your project's guides and refuses anything that would steer an agent around you. Every finding names its line.

  • 03

    Approve it, or share it

    Approve it in Settings → Guides → Write your own. Agents use it only after you do, and again after every edit. To share it with everyone, send it to the catalog: how to contribute a guide.
