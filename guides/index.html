Why guides

A general-purpose agent is a generalist. Your trail isn't.

The same agent that writes the code shouldn't be the one that signs it off, and a security pass needs a different eye than a docs pass. Guides give each kind of work its own instructions and its own bar.

How it works

Pick them, add them to the party, and they work to the checklist.

  • 01

    Pick a guide

    Browse a moderated catalog of roles, or write your own. Each one is a short file: instructions, a checklist and the checks it needs.

  • 02

    Add them to the trail

    Tickets say which role they need, and the trail lists its party. Scout routes each ticket to an agent that can take it.

  • 03

    They work to their checklist

    The agent that claims the ticket gets the role's instructions and checklist, and can't finish until every item is answered.

Safe by design

A guide can raise the bar. Never lower it.

Bringing someone in from a catalog has to be safe by default. These rules are enforced by Teamtrail, not by the role.

  • No code in a role

    Roles are instructions and checklists. No scripts, no hooks, nothing that runs on install.

  • You approve every check

    A command a role proposes runs only after you approve it, and it goes into your repo's config.

  • Pinned and verified

    Each installed role is pinned to a version and fingerprint. A file that changes is switched off until you look.

  • Roles only add rules

    A role can add checks and checklist items. It can't skip review, lower verification or decide for you.

Any agent can wear the role

Guides aren't tied to a model.

A role is plain text that travels with the ticket. Claude Code, Codex or any agent that connects over MCP picks it up when it claims the work. No vendor lock-in, no hosted agents, and still all on your machine.
